# m2 · v0.2 — trustworthy under real use

**Goal:** take the working fabric from "demo on a cable" to "I reach for it daily."
The gaps that show up the moment real commands and real networks are involved.

## Items

- [`KN-EXEC-020`] — robust signal forwarding (SIGINT/SIGTERM, process-group aware),
  designing the client→server framing path KNIT2 will formalize. Builds on the
  v0.1 SIGINT groundwork ([`KN-EXEC-010`](m1-v0.1-fabric.md)).
- [`KN-DISC-020`] — `--peer host:port` and `KNIT_PEERS`, skipping mDNS. This is
  what makes knit work across a Tailscale tailnet or any multicast-filtered
  network, inheriting the overlay's encryption and identity.
- [`KN-EXEC-030`] — `run --dir` / `--sync`: rsync-style working-directory sync for
  commands that need files, not just stdin. The biggest single expansion of what
  `run` can do; content-hash delta transfer so large trees stream.
- [`KN-CLIENT-020`] — `ls` marks the interface a peer was found on
  (thunderbolt/ethernet/wifi), the groundwork for v0.3 link preference.
- [`KN-OPS-020`] — `goreleaser` pipeline: tag → four binaries, checksums, release.
- [`KN-OPS-021`] — Homebrew tap, so `brew install knit/tap/knit` is the
  headline install path.

## Definition of done

- Ctrl-C and `kill` behave; no orphaned remote processes under any exit path.
- knit works over a tailnet with `--peer`, no mDNS required.
- A command that needs a directory of inputs runs remotely via `--dir`.
- `brew install` puts a working `knit` on a fresh machine.

## Theme

Everything here is about *trust in daily use*: predictable signals, reachable peers
beyond the local segment, real inputs, and a real install. No new grand capability —
just removing every reason to fall back to SSH.
