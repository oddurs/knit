# m1 · v0.1 — the fabric

**Goal:** two machines, one cable or LAN, with `run` / `each` / `ls` working end to
end — fast and seamless from the first command. This is the milestone that proves
the whole idea; everything after it is refinement.

Items are tracked in [`../registry.toml`](../registry.toml); live status in
[`../STATUS.md`](../STATUS.md). Numbers below are the dependency-sorted build order.

## Definition of done

- `knit up -d` on two machines; `knit ls` shows both plus self, with live load.
- `cat file | knit run -- <cmd> > out` streams at link rate, exits with the
  command's code, prints one dim line only when the work left the machine.
- `knit each -- <cmd>` fans out with `[name]` prefixes and an aggregate exit code.
- Verified over both a Thunderbolt bridge and Wi-Fi ([`KN-TEST-003`](../registry.toml)).
- `go test -race ./...` green; the 0-alloc framing invariant asserted in a bench.

## Build order and rationale

**Foundations (no dependencies, build first, in parallel):**

- [`KN-PROTO-001`] — wire types, framing, version token, error codes. The spine
  everything on the wire sits on. Framing must be 0-alloc and one `writev` per
  frame from day one ([performance](../../docs/10-performance.md)).
- [`KN-AUTH-001`] — keyfile + HMAC-nonce. The entire security boundary
  ([security model](../../docs/08-security-model.md)).
- [`KN-SYS-001`] — cores/memory/load, darwin+linux, parser-tested against fixtures.
- [`KN-DISC-001`] — mDNS register + browse on all interfaces. The zero-config
  magic and the reason the cable needs no special code.

**Seams:**

- [`KN-DISC-002`] — the ~5 s peer cache that makes the *second* command instant.
  Small, but it is most of the "seamless" feeling ([ADR-0003](../../docs/adr/0003-mdns-discovery-and-cache.md)).
- [`KN-CLI-001`] — `key` / `join`, the one-command pairing flow.
- [`KN-XPORT-001`] — dial + handshake, `TCP_NODELAY` on, typed errors.

**The agent and the execution core (the heart):**

- [`KN-AGENT-001`] — listener, auth gate, op dispatch, `up`/`up -d`/`down`.
- [`KN-EXEC-001`] — spawn, stream stdio with pooled buffers, relay the exit code.
  Binary-clean and allocation-free in steady state.
- [`KN-EXEC-010`] — SIGINT forwarding so Ctrl-C reaches the remote process and
  leaves no orphan. The v0.1 90% answer ahead of full KNIT2 signal framing.

**The client and the entrypoint:**

- [`KN-SCHED-001`] — load-per-core scoring, local always a candidate, `--on`.
- [`KN-CLIENT-001`] — `ls` with parallel 250 ms probes, table + stable `--json`.
- [`KN-CLIENT-002`] — `run`: schedule, invisible local fallback, stream, exit relay.
- [`KN-CLIENT-003`] — `each`: fan-out, prefixing, aggregate exit.
- [`KN-CORE-001`] — `main()` dispatch, usage, the exit-code contract.

**Making it real:**

- [`KN-OPS-001`] — static CGo-free build with version stamping.
- [`KN-TEST-001`] — unit + protocol + loopback e2e + race + fuzz.
- [`KN-TEST-002`] — CI wiring, including `roadmap.py check` gating the plan.
- [`KN-TEST-003`] — the two-machine manual matrix that backs the speed claims.
- [`KN-DOC-001`] — repo-root README, SECURITY.md, quickstart.

## The one loopback smoke test that means "it works"

```sh
knit up -d
knit ls
echo hi | knit run --on "$(hostname -s)" -- cat     # prints: hi
```

When that round-trips with the right exit code and `ls` shows the machine, the
fabric is alive on one box. `KN-TEST-003` then proves it across the cable.

## Risks carried into m1

- **mDNS on odd networks.** Some LANs filter multicast. Mitigation is m2's
  `--peer` ([`KN-DISC-020`](m2-v0.2-real-use.md)); m1 assumes a friendly LAN/cable.
- **Signal semantics.** Full signal framing is KNIT2; m1 ships the SIGINT 90%
  case and documents the edge.
