# m4 · v0.4 — encrypted, persistent, shareable

**Goal:** close the security gaps v1 documented honestly, let agents survive
reboots, and open the second resource an agent can share — the network — now that
the link can be trusted.

## Items

- [`KN-AUTH-040`] — **TLS 1.3 with a key-bound handshake.** Every connection
  is TLS 1.3 with an ephemeral certificate; both ends prove the shared key bound
  to that connection, so an impostor or a relay is refused — still zero-config,
  no cert state. Closes the plaintext confidentiality, integrity, and
  server-authentication gaps ([ADR-0009](../../docs/adr/0009-tls-key-bound-handshake.md),
  superseding the pinning sketch in ADR-0008; [security model](../../docs/08-security-model.md)).
- [`KN-OPS-040`] — `knit up --forever`: launchd (macOS) / systemd (Linux) units
  so the agent survives reboot, and `knit down` removes them.
- [`KN-AUTH-041`] — key rotation UX (`knit key --rotate`), reporting which
  machines must re-join; atomic, and the agent needs no restart.
- [`KN-NET-040`] — **`knit proxy`**: a local SOCKS5 listener tunneling through a
  peer's agent connection. **Deferred** now that TLS is in: it would be the eighth
  command, and Tailscale exit nodes and macOS Internet Sharing already cover its
  use cases. Kept coded so it is never lost.

## Definition of done

- Every connection is encrypted and mutually authenticated, with no new config
  steps for the user.
- Agents come back after a reboot.
- (`knit proxy` deferred; see above.)

## Sequencing

`KN-AUTH-040` first and alone gates the milestone's value: it is the difference
between "trusted cable only" and "safe on any network," and it is the hard
prerequisite for `KN-NET-040`. The validator enforces that ordering — `KN-NET-040`
is marked `blocked` on `KN-AUTH-040` in the registry.
