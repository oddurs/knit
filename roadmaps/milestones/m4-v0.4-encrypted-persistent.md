# m4 · v0.4 — encrypted, persistent, shareable

**Goal:** close the security gaps v1 documented honestly, let agents survive
reboots, and open the second resource an agent can share — the network — now that
the link can be trusted.

## Items

- [`CX-AUTH-040`] — **TLS 1.3 with pinned self-signed certs.** Each machine
  self-signs on first run; `join` exchanges and pins fingerprints alongside the
  shared key; connections then run TLS 1.3 with mutual pinned verification — still
  zero-config. Closes the plaintext confidentiality, integrity, and
  server-authentication gaps ([ADR-0008](../../docs/adr/0008-tls-pinned-certs-v04.md),
  [security model](../../docs/08-security-model.md)). This is the keystone of the
  milestone; everything sensitive waits on it.
- [`CX-OPS-040`] — `connex up --forever`: launchd (macOS) / systemd (Linux) units
  so the agent survives reboot, and `connex down` removes them.
- [`CX-AUTH-041`] — key rotation UX (`connex rotate`), reporting which machines
  must re-join. The mechanism (overwrite the keyfile) works today; this makes it
  humane.
- [`CX-NET-040`] — **`connex proxy`**: a local SOCKS5 listener tunneling through a
  peer's agent connection, reusing the exact `run` auth + streaming machinery via a
  new `dial host:port` op. **Blocked on `CX-AUTH-040` by policy** — proxied traffic
  is too sensitive for a plaintext link, so this ships only after TLS and refuses to
  run without it.

## Definition of done

- Every connection is encrypted and mutually authenticated, with no new config
  steps for the user.
- Agents come back after a reboot.
- A laptop on hotel Wi-Fi can route through a wired peer with `connex proxy`.

## Sequencing

`CX-AUTH-040` first and alone gates the milestone's value: it is the difference
between "trusted cable only" and "safe on any network," and it is the hard
prerequisite for `CX-NET-040`. The validator enforces that ordering — `CX-NET-040`
is marked `blocked` on `CX-AUTH-040` in the registry.
